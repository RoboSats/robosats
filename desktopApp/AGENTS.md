# /desktopApp — Electron Desktop App

## Purpose
Electron shell that supervises a bundled Tor binary, configures the renderer session
to proxy all HTTP/WS through it, and routes `file://` asset requests to local build
outputs. The UI entirely lives in `/frontend`; this directory contains no product logic.

## Architecture
```
Module load
  └── checkPlatformAndRunTor()          ← spawn Tor binary (no torrc, no args)
        ├── stdout → console.log
        └── stderr → app.exit(1)        ← HARD EXIT, no fallback

app.whenReady() → createWindow()
  └── BrowserWindow 1200×800
        └── loadURL file://…index.html#/garage

app.on("ready")
  ├── onBeforeRequest { urls: ['file:///static/*'] }
  │     └── url.slice(7) → path.join(__dirname, …) → redirectURL
  └── setProxy { proxyRules: "socks://localhost:9050",
                 proxyBypassRules: "<local>" }

window-all-closed → tor?.kill() → app.quit() (non-darwin)
```

Child docs (load on demand):
- `desktopApp/tor/AGENTS.md` — Tor Expert Bundle layout, invocation, provenance, traps

## Startup / Control Flow
1. **Tor launch** — at module load (`checkPlatformAndRunTor()`), before `app.ready`:
   - `win32` → `__dirname/tor/tor-win/tor/tor.exe`
   - `darwin` → `__dirname/tor/tor-mac/tor/tor`
   - `linux` → `__dirname/tor/tor-linux/tor/tor`
   - Unsupported platform → `throw new Error(...)` (unhandled, app crashes)
2. **Tor monitoring** — `TorMonitor` (in `torMonitor.ts`) attaches to the process
   stdout/stderr/exit streams immediately after `spawn()`:
   - Parses `Bootstrapped N%` lines and logs progress.
   - On `Bootstrapped 100%`: clears the 90-second timeout; nothing else needed.
   - On `[err]` / missing-protocol line / process exit / 90-second timeout:
     shows a native `dialog.showMessageBox` with Tor's own error text and a
     button to open `https://github.com/RoboSats/robosats/releases/latest`, then calls
     `app.exit(1)` — fail-closed.
3. **Window** — `BrowserWindow` 1200×800, icon `static/assets/images/favicon-32x32.png`,
   `nodeIntegration: false`, `contextIsolation: true`; loads
   `file://${path.resolve(__dirname, 'index.html#/garage')}` with `pragma: no-cache`.
   `did-fail-load` retries using a differently-constructed URL
   (`file://${__dirname}/index.html#/garage` — different `path.resolve` vs bare concat).
4. **Session** (`app.on("ready")`, distinct from `app.whenReady()`):
   - `file:///static/*` → rewrites to `file://${path.join(__dirname, url.slice(7))}`
   - Proxy: `socks://localhost:9050`, bypass `<local>`

## Frontend Contract
| Concern | Value |
|---|---|
| `window.RobosatsSettings` | `'desktop-basic'` — injected by shared `frontend/templates/frontend/index.ejs` |
| UI mode | `RobosatsSettings.split('-')[1] === 'basic'` → `BasicMain`; no desktop-pro entry exists |
| API client | Selected at **module load** from `window.navigator.userAgent` — `AndroidRobosats` UA → `ApiAndroidClient`; default → `ApiWebClient`. Desktop UA is `Electron` (not `'android'`), so desktop always gets `ApiWebClient`. Selection is **not** from `window.RobosatsSettings`. |
| Origin | `getOrigin()` forces `origin = 'onion'` when `client === 'desktop'` |
| Settings | `getSettings()` returns plain `Settings` (not `SettingsSelfhosted`) |
| JS↔native bridge | **None** — no `window.AndroidAppRobosats` equivalent; `fetch`/`WebSocket` go through Tor at the session level |

## Build & Packaging
**Bundle generation** — `frontend/webpack.config.ts` (not any script in this dir):
- `HtmlWebpackPlugin` emits `desktopApp/index.html` with `publicPath: './static/frontend/'`
  (relative path — Android uses the same relative path; only web/selfhosted/nodeapp targets use `/static/frontend/` absolute).
- Inline `afterEmit CopyFilesPlugin` copies `frontend/static` → `desktopApp/static`.

**Compile TypeScript** — manual, never run by CI:
```bash
cd desktopApp && npm run compile   # tsc → index.js + index.js.map; commit the output
```

**Package** (after bundle + compile):
```bash
npm run package-linux  # → release-builds/Robosats-linux-x64/
npm run package-win    # → release-builds/Robosats-win32-x64/
npm run package-mac    # → release-builds/Robosats-darwin-x64/
```
All use `npx @electron/packager . Robosats --overwrite --out=release-builds`.

**CI pipeline** — no manual steps at all in CI:
1. `.github/workflows/frontend-build.yml` → webpack → artifact `desktop-main-static`
   (contents: `desktopApp/static` + `desktopApp/*.html`).
2. `.github/workflows/desktop-build.yml` — `ubuntu-latest`, Node 22; downloads
   `desktop-main-static` into `desktopApp/`; `npm ci`; runs `node tor/verify.js`
   (binary checksum + version guard) then `npm test`; runs `package-mac`,
   `package-win`, `package-linux` (all three cross-compiled on Linux); **never runs
   `npm run compile`**; zips each `release-builds/` tree.
3. `.github/workflows/release.yml` — `needs: [frontend-build, desktop-build]`; uploads
   `robosats-desktop-{semver}-{mac-darwin-x64|linux-x64|win32-x64}.{short_sha}.zip`.

## Product Intent
- **Tor is mandatory and non-optional** — there is no clearnet mode, no system-Tor
  fallback, no Orbot-style escape hatch. The `app.exit(1)` on any Tor stderr is the
  deliberate fail-closed policy: leak no traffic if Tor fails.
- **Desktop is basic-only** — `BasicMain` targets a broad audience with a simple,
  mobile-like UX. Pro traders wanting the dashboard are expected to use the self-hosted
  `nodeapp/pro.html` or the web-pro URL. There is intentionally no desktop-pro HTML entry.
- **`#/garage` start is intentional** — robot identity setup is the mandatory first step
  before any trade. Every session begins there by design.

## Traps
1. `index.js`, `index.js.map`, `torMonitor.js`, `torMonitor.js.map` are tsc output
   **committed to git** — CI never recompiles. Edit `index.ts` or `torMonitor.ts`,
   run `npm run compile`, and commit all four outputs together.
2. `express` and `cors` are in `dependencies` but **never imported** — dead deps.
3. The `build` block in `package.json` is an electron-builder config that **no installed
   tool reads** — real packaging uses `@electron/packager` (`release-builds/`), not
   electron-builder (`dist/`).
4. The bundle filename contains the version from **`frontend/package.json`**, not
   `desktopApp/package.json`. The two version fields are maintained independently and can
   drift.
5. `index.html` contains a `window.WebAssembly` gate (from the shared `.ejs`) — if
   WebAssembly is absent, the UI shows `.noscript-error` silently instead of loading.
6. `index.html` contains `<meta http-equiv="onion-location" content="{{ ONION_LOCATION }}" />`
   — a literal Django template placeholder, never rendered; inert but visually confusing.
7. **Window opens before Tor bootstraps** — `TorMonitor` emits progress but does not
   block the `BrowserWindow` from loading. Coordinator API calls fail until Tor is ready.
   This is intentional: the UI can display a loading state before the proxy is live.
8. **Two different `file://` URL constructions**: `loadURL` uses `path.resolve(__dirname,
   'index.html#/garage')` (correct); `did-fail-load` uses bare `${__dirname}/index.html#/garage`
   (may also fail on the same root cause) — retry can loop.
9. `desktop-build.yml`'s `on.push`/`on.pull_request` path filter is
   `paths: [ "desktopApp/**" ]` — only `desktopApp/` changes trigger the build on
   push/PR. `frontend/**` was deliberately removed: PR builds would download the bundle
   from the last `main` run anyway (PRs don't run `frontend-build.yml`), making the
   trigger misleading and expensive. Release builds are always triggered via
   `workflow_call` from `release.yml` regardless of paths.

## Constraints
- Never hand-edit `index.js` or `index.js.map` — edit `index.ts`, run `npm run compile`,
  and commit the outputs together.
- Never hand-edit or commit `index.html` or `static/` — these are webpack outputs; change
  `frontend/webpack.config.ts` or `frontend/templates/frontend/index.ejs` instead.
- Never add a clearnet network path or relax the fail-closed policy (Tor failure dialog + `app.exit(1)`).
- Never set `nodeIntegration: true` or `contextIsolation: false`.
- Do not add a desktop-pro HTML entry point without explicit product sign-off.
- Do not rely on the `build` block in `package.json` — it is dead.
